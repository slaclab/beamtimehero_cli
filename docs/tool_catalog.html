§0 How the catalog works

Every tool is an OpenAI-style JSON-schema function definition in tool_catalog/definitions.py — one flat list, no decorators, no registration magic. categorize() assigns each definition to a branch of the CLI tree; a definition can also pin its own branch, which is how the same tool name (say list_scans) exists under both spec-file and s3df with identical schemas but different backends.

The CLI surface is generated from those schemas: tool plot_scan becomes beamtimehero spec-file plot-scan, and each JSON-schema parameter becomes a --kebab-case flag. That nested --help-at-every-depth surface is the LLM agent's discovery mechanism; this page is the same catalog laid out for humans.

Two safety conventions run through everything: every tool on spec-write requires --justification, and every CLI invocation — read or write — is recorded in the local SQLite action log (query it via the db branch).
